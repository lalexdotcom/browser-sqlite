# Follow-up — `backpressure` leaves an IndexedDB connection open on Safari 27.2, and the whole cell fails behind it (2026-11-18)

**Status: CLOSED 2026-11-19 — cause found and fixed in the test (`test/backpressure-kill-parked`, merged on the user's "Ok enchaîne"; the four spike branches deleted, local and origin).** Left open, raised to the user and not decided: the amplification (one strand fails every later file of the cell); test 2's restart of 2026-11-18, never seen again. Was: seen twice, not investigated (user, 2026-11-18: a chantier of its own, before the next release). Would refuse a release (`untag`).

Part of `mem:follow-ups`.

- **Seen:** the `platform.yaml` runs of `test/relative-duration-bets` on `macos-26` (Safari 27.2), 2 runs of 2 that day: run 44271372502, `safari · IDBBatchAtomicVFS/async` — `backpressure.test.ts` › "does not restart the worker when a stream is abandoned" red (`expected 2 to be 1`: the worker was restarted, `[SQLite 2] restarting worker 1` after `client closing`), then every later file of the cell red; run 44290943096, `safari · IDBBatchAtomicVFS/jspi` — every test of `backpressure.test.ts` green but the file red at teardown, then every later file. Each later file fails the same way: `This file left storage behind that could not be wiped: IndexedDB "IDBBatchAtomicVFS" (still open after 10000 ms)` (`tests/browser/helpers` storage wipe). Not seen on `xcode-27` (Safari 27.0.1) that day, nor on `main`'s macOS 26 runs of 2026-11-16 and 2026-11-17 (Safari already 27.2 there). The branch changes neither `backpressure.test.ts` nor the library.
- **Hypothesis, not verified:** `backpressure`'s "reclaims a worker killed while it is parked on a credit" (or the drain-timeout restart above) terminates a worker holding `IDBBatchAtomicVFS`'s IndexedDB connection, and Safari keeps that connection open after the worker is gone — the kill path of the old `mem:follow-ups/safari-idb-stranded`, whose fix (wa-sqlite #384/#385) covers `close()` only. The first sighting also shows a worker not answering its stop within `drainTimeout` on Safari, a duration of the library against a slow engine.
- **Two problems to separate:** (1) why the connection stays open; (2) the amplification — one leftover connection turns ~40 later files of the cell red, so a single fault reads as a broken pair.
- **Measured 2026-11-19 (macOS 26 runners, Safari 27.2, spike branches `spike/safari-backpressure-idb` and `-held`, each test of `backpressure.test.ts` alone in its own file and planner run, Safari quit between runs, `BSQ_TIME_SCALE` 2; verdict STRAND = the storage wipe saw "still open"):** runs 44530733767 (all six tests, 12 rounds; `jspi` stopped at round 9 by a `bash -e` in the loop) and 44547722341 (tests 2 and 3, 25 rounds). **Test 3 ("reclaims a worker killed while it is parked on a credit") strands on `jspi`: 2 of 34 runs; 0 of 37 on `async`.** The test itself passes; the file fails at the wipe. **Test 2 (the library's restart path) never: 0 of 37 `async`, 0 of 34 `jspi`**; the other four tests 0 of 12-21. **Cause of test 3's strand (hypothesis confirmed):** its consumer keeps pulling a chunk every 50 ms, so credits keep flowing and the worker steps again (IndexedDB reads) between the moment the test sees `awaiting-credit` and `killSilently` (a native `terminate()`, past the pool's `quiesce`): a readonly transaction live at the kill, WebKit 324094 (`mem:follow-ups/safari-idb-stranded`). **Variant with the consumer held before the kill** (blocks on a gate, then waits for `awaiting-credit` again, plus a spike-only `sleep(scaled(300))`), run 44548623372, 50 rounds per build: **0 of 100** (50 `async`, 50 `jspi`). Trap paid: GitHub's bash runs with `-e`, which `set -uo pipefail` does not undo (`set +e` does); and a spike step that ran `Safari --version` opened Safari's GUI and hung 3 h (run 44502828095, nothing measured).
- **The whole cell, test 3 held** (`spike/safari-backpressure-cell`, run 44557099625, 2026-11-19, `test-matrix.ts --pair <pair> --engine safari` in a loop for 120 min, Safari quit between cells): **`IDBBatchAtomicVFS/async` 12 cells of 12 green, `/jspi` 31 of 31, no "still open", no `backpressure` failure.** So nothing else in the cell strands IndexedDB, and test 2's restart of 2026-11-18 did not recur in 43 cells (nor in 71 isolated runs). No control arm with the original test 3 in the cell: the isolated runs are the control. The `restarts` count of that run is not evidence: a passing test's console is silent (`silent: 'passed-only'`).
- **The fix, test only (`test/backpressure-kill-parked`, 2026-11-19):** test 3's consumer holds before the kill, and the kill waits until the worker has received `DEFAULT_CREDIT_WINDOW` + credits sent chunks and its last message is `run` (`awaiting-credit`) — parked with no credit left, no sleep. Falsified by removing `gate.take` from the worker (red, timeout). Local: `pnpm test` 423/423 files, 3 305 passed; the file 3 times on every Chrome/Firefox pair, 44/44. **Safari 27.2, the committed test (`spike/safari-backpressure-parked`, run 44584783892, 50 rounds per build): 0 strands in 100.** Not decided: the amplification (one strand fails every later file of the cell), a test-tooling question.
