# Test planner — the browser suite without identical repetitions (design in discussion, 2026-10-12)

Brainstorming with the user, architectural path: decisions are taken point by point, the user validates each before the next. A spec goes to `docs/superpowers/specs/` once the design is approved; nothing is implemented before. This file holds what is DECIDED so far; reread it before resuming.

## Why
Every pinned test (`createTestClient({ vfs })`, a VFS constant, a literal in `createSQLiteClient`) ran in every target project: 44 identical runs per matrix. Measured 2026-10-11 by a traced run (target reads and workers per test, throwaway worktree): 343 tests read the target, ~102 open a VFS without it (pinned), 10 use no VFS, 13 are synchronous guards. The isolated column ran 9 tests, all pinned to `OPFSWriteAheadVFS/sync`. Two CI failures of the first GitHub matrix (abort-slot timeout, abandon GC) were in such tests. Static inventory under-counts: VFS constants, describe-scoped helpers and module-scope `TEST_TARGET` reads (`vfs-folders` l.11, `delete` l.271, `second-client` l.141) fool it.

## Decided
- **Two series.** (1) Tests bound to a (vfs, build) pair, filtered by a need. (2) Tests with no VFS, or that only compare VFS through a constant: once per browser, out of the matrix ("a kind of browser unit test"). A multi-VFS test takes the target as one side and the first pair satisfying a need as the other (no such test exists today).
- **Need = what the TEST requires**, not a VFS description. `shouldTestRun({ vfs, build, browser, isolated, features }, need) → boolean`, pure, unit-tested. `TestNeed = { browser?, vfs?, build?, isolated?, requires?: Property[], excludes?: Property[] }`; AND across fields, OR inside a list. No need = runs everywhere non-isolated.
- **Isolation dedupe rule** (in the helper): in an isolated context a test without `isolated: true` runs only if isolation makes it eligible (eligible isolated AND not eligible non-isolated). Code-verified: isolation only changes the `sync` build's slot channel (`client.ts:425` allocates, only the sync worker reads it). Isolated cells exist only where non-empty (the 4 `sync` pairs); empty cells are never launched. `isolated/environment` becomes a project precondition check that fails the run, not a test.
- **Needs as literal Vitest tags** (`it(name, { tags: ['requires:two-workers', 'build:sync'] }, fn)`, or on the describe): static collection reads them in ~1 s with no browser (measured: 137 modules, 0.8 s); constants, computed values, wrappers and `${}` loops are NOT read. Vitest refuses undeclared tags, which enforces the closed vocabulary. Generated-by-loop tests disappear (tests follow the target).
- **Features from one small probe per environment** (browser × isolated): page probes + worker probe (`readwrite-unsafe` only from a worker). The planner decides with the library's own `detectFeatures`. A cell re-checks at collection; any mismatch with the plan fails loudly.
- **Node API, not `vitest list`**: `vitest.collect(undefined, { staticParse: false })` loads files in real browsers and returns `meta` + skipIf results; the CLI `list` parses statically by default and its JSON has no meta; reporters are not called in list mode.
- **`pnpm test` = early catch, the matrix = verdict.** Start list: VFS only (`RECOMMENDED_VFS`), build resolved per browser by `defaultBuildFor` from probed features (never a hard-coded pair; an explicit `BSQ_TEST_TARGETS` pair is never substituted — not applicable on a browser = shown, not run). Start pairs run ALL their eligible tests; the remaining tests go to a complement: each to the **first eligible pair in canonical order** (VFS_CAPABILITIES keys, then builds in declared order, filtered by the browser). Stable, explainable. Browsers are NOT merged (capabilities do not model engine implementations; Firefox-only failures are this repo's history). The matrix runs on every push of `main`.
- **Reporting**: "not applicable on a browser" is listed with the missing need, never a failure; compare that list when a browser pin changes. "Dead" (eligible on no pair of any browser) fails the matrix and CI, warns locally.
- **`fallback`/`skip` (`BSQ_TEST_NEEDS`) and pinning disappear.** Direct Vitest runs bypass the plan: scripts take files through the plan; a project run outside the plan warns. `test:watch` removed (2026-10-12, merged).
- **Scripts**: `test`; `test:chrome`/`test:firefox` = both modes, deduped like the matrix; `test:chrome:not-isolated`, `test:chrome:isolated` (and Firefox) = that mode in full; `test:isolated` = both browsers isolated.
- **Guards to `unit`**: reorder `createSQLiteClient` and `deleteDatabase` so the common guards run in one order — vfs required, vfs/build combination, names, own guards (pool + pragmas / memory early return), `missingFeature`, then the `.wasm` URL (in delete, only when the delete worker starts). Measured in a throwaway worktree: the 12 guards and the init-lock BUSY test then run in Node with no stub, unit 766/766 and 7 browser files 220/220 green. User-visible: an invalid pragma on a browser without OPFS now reports INVALID_PRAGMA; the `wasmUrl` callback is not called when a guard throws (CHANGELOG Changed). Guard tests iterate `VFS_CAPABILITIES` instead of pinning (covers IDBMirrorVFS's cap). BUSY picks the first persistent VFS runnable in the environment through the same need helper (Node features = `web-locks` only → IDBBatchAtomicVFS today); it fails loudly if none.

## Proposed, not yet validated
- Property vocabulary (requires/excludes), each computed from declarations: two-workers, interruptible, shared-second-client, shared-storage, opfs-file, in-place-file, capped-pool, exclusive-connection, env-capped-pool, default-pragmas, exclusive-file-handle, idb-storage. Negation via `excludes`, no opposite names. `vfs` lists only for genuinely VFS-specific subjects (OPFSCoopSyncVFS hand-over, OPFSWriteAheadVFS barrier pragma). Slot channel = `build: sync` + `requires: interruptible`; degraded path = `build: sync` + `excludes: interruptible`.
- Remaining points: "eligible ≠ necessary" (keep all eligible pairs by default), browser as a constraint (in TestNeed already).

## Noticed, out of scope
The IndexedDB VFS declare no IndexedDB requirement, so `missingFeature` passes where IndexedDB is absent (Node shows it). Fixing it would move the BUSY test out of Node.
