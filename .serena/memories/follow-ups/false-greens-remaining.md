- **`abort-slot` and `early-exit` (4 tests): a step cut, or a boundary stop?** Each reads the first row of a query whose second row is a 2 G-row count in one `sqlite3_step()`, leaves (a `break` out of `chunk()`, or `first()`), and proves the step was cut because `SELECT 1` is served at once. If the worker had not yet entered the count when the stop came (still handing over row 1, or waiting for credit), it stops at the row boundary, nothing is cut, and the test passes with the cutting code broken. The `chunk()` variants give it `sleep(100)`; the `first()` variants nothing. **Fixed on `feat/debug-run-stage` (2026-11-05, awaiting merge):** the `chunk()` tests wait for the `computing` run stage before the `break`, the `first()` tests read the query's `stages.computing` after the next `SELECT 1`; a miss goes through `exercised` (`mem:follow-ups/debug-run-stage`).
