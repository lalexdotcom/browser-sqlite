# Follow-up — `backpressure` leaves an IndexedDB connection open on Safari 27.2, and the whole cell fails behind it (2026-11-18)

**Status: OPEN** — seen twice, not investigated (user, 2026-11-18: a chantier of its own, before the next release). Would refuse a release (`untag`).

Part of `mem:follow-ups`.

- **Seen:** the `platform.yaml` runs of `test/relative-duration-bets` on `macos-26` (Safari 27.2), 2 runs of 2 that day: run 44271372502, `safari · IDBBatchAtomicVFS/async` — `backpressure.test.ts` › "does not restart the worker when a stream is abandoned" red (`expected 2 to be 1`: the worker was restarted, `[SQLite 2] restarting worker 1` after `client closing`), then every later file of the cell red; run 44290943096, `safari · IDBBatchAtomicVFS/jspi` — every test of `backpressure.test.ts` green but the file red at teardown, then every later file. Each later file fails the same way: `This file left storage behind that could not be wiped: IndexedDB "IDBBatchAtomicVFS" (still open after 10000 ms)` (`tests/browser/helpers` storage wipe). Not seen on `xcode-27` (Safari 27.0.1) that day, nor on `main`'s macOS 26 runs of 2026-11-16 and 2026-11-17 (Safari already 27.2 there). The branch changes neither `backpressure.test.ts` nor the library.
- **Hypothesis, not verified:** `backpressure`'s "reclaims a worker killed while it is parked on a credit" (or the drain-timeout restart above) terminates a worker holding `IDBBatchAtomicVFS`'s IndexedDB connection, and Safari keeps that connection open after the worker is gone — the kill path of the old `mem:follow-ups/safari-idb-stranded`, whose fix (wa-sqlite #384/#385) covers `close()` only. The first sighting also shows a worker not answering its stop within `drainTimeout` on Safari, a duration of the library against a slow engine.
- **Two problems to separate:** (1) why the connection stays open; (2) the amplification — one leftover connection turns ~40 later files of the cell red, so a single fault reads as a broken pair.
- **Next:** reproduce on `macos-26` with a spike workflow looping `backpressure.test.ts` on `IDBBatchAtomicVFS/async` and `/jspi` (`mem:lessons/process`, a dedicated push-triggered workflow), naming which test leaves the connection open; then decide between the library (closing the connection before a terminate), the test, or a WebKit report.
