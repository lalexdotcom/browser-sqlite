# `db.ready` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `db.ready: Promise<void>`, which settles when the client's pool has finished starting, and make the bench show the pool size a column actually ran on.

**Architecture:** A deferred owned by `createSQLiteClient`, settled at the three places the startup verdict is known — the end of `onGateOpen` (resolve), `failClient` (reject with the fatal error), `close()` (reject with `CLIENT_CLOSED`). It is NOT derived from the scheduler's gate, which resolves before `onGateOpen` may still fail the client (spec §2).

**Tech Stack:** TypeScript, rstest (browser mode, Playwright Chromium and Firefox), biome.

**Spec:** `docs/superpowers/specs/2026-09-23-db-ready-design.md` — read it whole before starting.

## Review Focus

1. **A consumer who never reads `ready` on a client that fails** — no `unhandledrejection` may surface. Pinned by Task 1, case 7.
2. **A pool empty at gate-open** — the gate opens, then `onGateOpen` fails the client; `ready` must reject, never resolve. Pinned by Task 1, case 4.
3. **`close()` right after creation** — the gate is rejected by `shutdown` and `onGateOpen` never runs; `ready` must still settle (reject `CLIENT_CLOSED`) rather than hang. Pinned by Task 1, case 5.
4. **A pool capped by its environment** — `db.poolSize` read right after `await db.ready`, with no query issued, must already be the effective size. Pinned by Task 1, case 2.
5. **A second client refused on an exclusive database** — `ready` must carry `DATABASE_IN_USE`, the same refusal its queries get. Pinned by Task 1, case 6.

`src/api.ts`, in the `SQLiteDB` type — replace `poolSize`'s JSDoc and add `ready` right after it:

```ts
  /**
   * The number of workers the pool runs: `poolSize` as requested, capped by
   * the VFS and by the environment. Exact once `ready` resolves — and every
   * query waits for that, so it is settled by the time any query returns.
   */
  readonly poolSize: number;
  /**
   * Settles once the pool has started: every worker has opened, declined, or
   * failed its one retry. Resolves when at least one worker serves the database;
   * rejects with the error that failed the client otherwise, and with
   * `CLIENT_CLOSED` when `close()` comes first. Never needs awaiting — queries
   * wait on their own — and never raises an unhandled rejection when unread.
   */

```

```md
## *client*.ready

`Promise<void>`, readonly. Settles once the pool has started: every worker has opened, been declined by the environment, or failed its one retry. It resolves when at least one worker serves the database, and [`poolSize`](#clientpoolsize) is final from then on. It rejects with the error that failed the client — `WORKER_CRASHED` when no worker could open, `DATABASE_IN_USE` when another client holds the database exclusively — and with `CLIENT_CLOSED` when `close()` comes first.

You never need to await it: queries wait for the pool on their own. It settles once — a worker lost later is reported by [`onWorkerLost`](#options), not here — and leaving it unread never raises an unhandled rejection.
```

Queries never need it: they wait for the pool as before.
