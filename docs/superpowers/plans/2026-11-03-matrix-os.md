# The Matrix as a Module, on Windows and macOS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `matrix.yaml` becomes a reusable module called by `ci.yaml` on Linux and by four dispatch-only callers (Ubuntu, Windows, macOS 26, macOS 27); the release finds one CI run instead of two.

**Architecture:** Workflow files only. `matrix.yaml` takes inputs (`runs-on`, `browsers`, `time-scale`, two timeouts, `fail-fast`) and keeps its `plan` + `cells` jobs; `ci.yaml` gains a `matrix` job calling it with `fail-fast: true`; the release's `prior` loop and separate `matrix` job shrink to CI alone. Proved on GitHub through a temporary `push` trigger on the branch, reverted before the merge.

**Tech Stack:** GitHub Actions reusable workflows, `scripts/test-plan.ts`, `scripts/test-matrix.ts`, actionlint.

**Spec:** `docs/superpowers/specs/2026-11-03-matrix-os-design.md`

## Global Constraints

- No change to the planner, `test-matrix.ts`, the tests or the setup action (spec § Non-goals).
- What the Linux matrix runs on a push of `main` or under the release is unchanged: same plan command, same pairs, four columns, `timeout-minutes: 25`, plan `15`, `fail-fast: true`.
- `checks: write` (with `contents: read`) on `matrix.yaml`'s `cells` job and on every job that calls it.
- `shell: bash` on every `run:` step of `matrix.yaml` (a `defaults.run.shell` per job is fine).
- `node scripts/actionlint.ts` and `pnpm exec biome ci .` clean after every task. Conventional Commits with the `Co-Authored-By` line. Nothing pushed or dispatched without the user's go.

## Review Focus

- A release whose push run of CI is missing or red → `verify` runs `ci.yaml`, matrix included, and `release` still needs it (no skipped need lets a red matrix through).
- A pull request from a fork → the matrix runs read-only (no progress published), its outcome unaffected.
- Windows: the browser loop and `--engine` arguments under Git Bash; the `time-scale` reaching both jobs.
- macOS: `safari` in `browsers` reaching the setup action (safaridriver enabled) in BOTH jobs, and `--engine safari --engine isolated-safari` in the pair jobs.
- A dispatch of an OS matrix while another of the same OS runs on the same ref → the newer cancels the older (concurrency), never a Linux CI run.

### Task 1: `matrix.yaml` as a module

**Files:**
- Modify: `.github/workflows/matrix.yaml`

**Interfaces:**
- Produces: `on: workflow_call` with inputs `runs-on` (string, required), `browsers` (string, default `chrome,firefox`), `time-scale` (string, default `'1'`), `timeout-minutes` (number, default 25), `plan-timeout-minutes` (number, default 15), `fail-fast` (boolean, default `false`). No other trigger, no workflow-level `concurrency`.

- [ ] **Step 1:** Replace the `on:` block by the `workflow_call` inputs above (descriptions in the style of `tests.yaml`); delete the `concurrency:` block and rewrite the header comment (a module; its callers in spec Goal 1).
- [ ] **Step 2: `plan` job.** `runs-on: ${{ inputs.runs-on }}`, `timeout-minutes: ${{ inputs.plan-timeout-minutes }}`, `env: { BSQ_TIME_SCALE: ${{ inputs.time-scale }}, BROWSERS: ${{ inputs.browsers }} }`, `defaults.run.shell: bash`; the setup action `with: browsers: ${{ inputs.browsers }}`; the plan step passes `--browser <b>` for each browser of `$BROWSERS` (the `IFS=, read -ra` loop of `tests.yaml`) to `node scripts/test-plan.ts --mode all-pairs --plan-only --pairs-out pairs.json`.
- [ ] **Step 3: `cells` job.** Same `runs-on`, `env` and shell; `timeout-minutes: ${{ inputs.timeout-minutes }}`; `strategy.fail-fast: ${{ inputs.fail-fast }}` (its comment: the gating callers pass `true`, a dispatch goes to the end); setup `with: browsers: ${{ inputs.browsers }}`; the `Matrix ${{ matrix.pair }}` step runs `node scripts/test-matrix.ts --pair "$PAIR"` plus `--engine "$b" --engine "isolated-$b"` for each browser (`PAIR` from `matrix.pair` through `env`, the progress `env` kept). Permissions, the report and the `Close progress` steps unchanged.
- [ ] **Step 4: Lint.** Run: `node scripts/actionlint.ts && pnpm exec biome ci .` Expected: exit 0. (actionlint will flag nothing calling the module yet; that is Task 2.)
- [ ] **Step 5: Commit** — `ci(matrix): make matrix.yaml a reusable module with inputs`.

### Task 2: CI calls the matrix; the release finds one run

**Files:**
- Modify: `.github/workflows/ci.yaml`, `.github/workflows/release-and-publish.yaml`

- [ ] **Step 1: `ci.yaml`** — a job `matrix` after `linux`: `permissions: { contents: read, checks: write }` (same comment as `linux`), `uses: ./.github/workflows/matrix.yaml`, `with: { runs-on: ubuntu-latest, fail-fast: true }`, no `if`. Comment: every pair through every column on Linux, whenever CI runs (pushes of `main`, pull requests, the release); fail-fast because CI gates. Update the `workflow_call` comment at the top if it names only the tests.
- [ ] **Step 2: release `prior`** — the loop `for WF in ci matrix` becomes CI alone (keep the 50-minute deadline and the `rerun`/`success` logic, drop the `matrix` output); its header comment says the push's CI run now holds the matrix.
- [ ] **Step 3: release jobs** — delete the `matrix` job; `untag.needs` and `release.needs` become `[prior, verify, consumer-smoke]`; rewrite `verify`'s comment (it runs the tests, the checks and the matrix when the push's run is not reusable).
- [ ] **Step 4: Lint.** Run: `node scripts/actionlint.ts && pnpm exec biome ci .` Expected: exit 0; actionlint checks the `with:` against `matrix.yaml`'s inputs.
- [ ] **Step 5: Commit** — `ci: run the matrix inside CI, and the release through CI alone`.

### Task 3: The four dispatch callers

**Files:**
- Create: `.github/workflows/matrix-ubuntu.yaml`, `matrix-windows.yaml`, `matrix-macos-26.yaml`, `matrix-macos-27.yaml`

Comments in the style of the matching `tests-<os>.yaml` (why the scale; why the timeouts, from spec Goal 7's paragraph; why Safari; why `xcode-27`).

- [ ] **Step 1:** Write the four files.
- [ ] **Step 2: Lint.** Run: `node scripts/actionlint.ts && pnpm exec biome ci .` Expected: exit 0.

### Task 4: Prove on GitHub

Every push and dispatch waits for the user's go.

- [ ] **Step 1: Temporary trigger**, in a commit of its own (`ci(temp): run the matrices on pushes of ci/matrix-os`): add `push: branches: [ci/matrix-os]` to `ci.yaml` and the four callers. actionlint clean.
- [ ] **Step 2: Push (user's go).** Expected: five runs start — CI (checks, linux, matrix) and the four matrices. Follow each with `node scripts/ci-watch.ts <run-id>` in the background and relay failures as they come.
- [ ] **Step 3: Expected results.** CI green, its `matrix` job 22 pairs + plan green, fail-fast. `Matrix (Ubuntu)` green, 22/22. Windows and macOS: whatever they show — record per pair the duration, the slowest pairs, the counts, every failure (spec Goal 10); none of their failures blocks the merge unless it comes from these workflows themselves (a wrong argument, a missing browser, a timeout below the planner's bound).
- [ ] **Step 4: Revert the temporary commit** (`git revert`), actionlint clean.
